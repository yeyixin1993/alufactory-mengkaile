# 萌开了官网升级交付说明

## 1. 候选版本身份

- 交付编号：`20260904-RC1`
- 交付性质：本地候选版，供代码审查与测试环境验收
- SketchUp 主插件：`铝型材DIY设计与拆分工具 v2.43.1`
- 轻量 SketchUp JSON 导出器：`MengkaileJsonExporter v1.1`
- 设计文件合同：`mengkaile-diy / schemaVersion 2`
- 来源凭证合同：`provenance / schemaVersion 1`
- 官网状态：本次制作交付包不上传仓库、不连接生产数据库、不修改正式网站

## 2. 本次建议合并的能力

### 2.1 来源信息全链路

插件导出的来源凭证会依次进入设计器、购物车、订单 JSON 和后台来源统计。来源字段继续放在既有 JSON 容器中，不新增数据库列，因此本阶段不需要生产数据库迁移。

来源状态必须保持以下边界：

- 本地插件或手动 JSON：`self_declared`
- 根据旧文件特征推断：`legacy_inferred`
- 旧订单没有来源：`legacy_unspecified`
- 只有未来经过登录鉴权和服务端签名的正式直连才能写为：`server_verified`

来源凭证只用于追溯和统计，不参与加工身份判断，也不参与重复订单指纹。重新导出造成的时间或文档编号变化不能绕过重复订单提示。

### 2.2 3.0 参数化展示架

- 固定：3030 型材、18mm 海洋板、Ø8 光轴、SK8/SHF8 组合、20°斜装层板、抽屉滑轨与既定装配规则。
- 可调：宽 400～1500mm、高 1500～3000mm、深 350～750mm、地柜高 600～1400mm、上部层板 1～5 层、下部抽屉 3～7 层。
- 每次生成重新计算构件数量、位置、孔位、攻丝和连接配件，固定构件禁止整体缩放代替重新生成。
- 自动层板布置保留至少 324.9mm 安全间距；刚好等于 324.9mm 的边界值允许生成，不会再被浮点误差误拦截。

### 2.3 构件与材料数据

- 型材、板件、光轴、夹具/支座、抽屉滑轨、连接件分别保留独立身份和统计类别。
- 没有官网 SKU 的构件以待补录的固定数据库记录进入材料统计，不能伪装成型材。
- 没有确认采购价的构件继续标记为待核价，不能自动使用猜测价格下单。

### 2.4 连接与加工自检

- 每个物理节点最多保留一条真实直锁路径，其余分支按规则改用可贴合的角码。
- 侧孔、端面攻丝、螺丝和角码必须来自同一连接结果。
- Ø8 光轴贯穿孔与支座安装孔分开处理；互斥位置不能叠加重复孔。
- 连接件必须同时贴合两个安装面，并通过占位、重复和物理干涉检查。

## 4. 网站主人合并步骤

1. 从正式仓库当前 `main` 建立独立候选分支，不直接修改 `main`。
2. 备份当前正式前端构建包、后端程序和生产数据库。
3. 解压 `01-网站源码`，与候选分支进行差异比较；不要整目录覆盖。
4. 由网站主人重新填写正式环境变量和支付配置，严禁复制测试环境的 `.env`。
5. 安装依赖并执行交付包中的测试命令。
6. 部署到测试域名，按《官网升级验收清单》逐项人工验收。
7. 验收完成后再合并 Pull Request、构建正式包并发布。
8. 插件 RBZ 与网页版本分别发布；官网正式直连未完成服务端鉴权前，来源仍显示“本地声明”。

## 5. 数据库与兼容性

- 来源全链路复用购物项现有的 `config.designSource` 和订单 JSON，不要求新增数据库字段。
- 旧购物车、旧订单和旧版 JSON 没有来源凭证时仍可读取，后台归为“旧数据（来源未记录）”。
- 新构件目录使用既有配件/型材数据接口；正式库存与价格必须由网站主人复核后录入。
- 不得删除或改名既有 SKU，也不得把新增夹具、光轴、滑轨替换成同尺寸型材。

## 6. 回退方法

1. 停止测试环境或正式环境继续接收新请求。
2. 把网页和后端恢复到发布前的提交或备份包。
3. 由于本阶段来源链路不新增数据库列，通常不需要回滚数据库结构。
4. 保留升级期间产生的订单 JSON；旧程序会忽略其中不认识的 `config.designSource` 字段。
5. 回退后重新验证旧产品、购物车、下单和后台订单读取。

## 7. 已知非阻断事项

- 前端构建存在大文件分包提醒，不影响当前功能；可在后续性能阶段再拆分加载。
- 后端测试会显示 SQLAlchemy `Query.get()` 的弃用提醒，但现有 10 项测试均通过；后续升级 SQLAlchemy 时再统一替换。
- 官网一键直传目前没有服务端签名和登录绑定，不应把本地来源标记成官网认证来源。
