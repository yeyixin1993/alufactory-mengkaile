# 萌开了项目 Codex 接续说明（2026-08-10）

> 用途：新 Codex 任务开始时先阅读本文，再阅读 `docs/DIY_DESIGNER_PROJECT_KNOWLEDGE.md` 和 `DIY_DESIGNER_IMPLEMENTATION.md`。本文是这次长期对话的交接摘要；源代码和产品知识文档仍分别是当前实现与产品规则的最终依据。

## 1. 仓库与发布基线

- GitHub：`yeyixin1993/alufactory-mengkaile`
- 当前开发方式：用户已确认直接在 `main` 修改和提交，不再使用旧的 `feature/3d-diy-designer` 开发分支，除非用户另行要求。
- 本地设计器统一使用 `http://localhost:3000/#/diy-designer`，不要额外启动 3001/3002 等端口。
- 前端构建：`npm run build`
- 完整本地前后端测试入口：`npm run dev:local`、`npm run test:local`
- 最新静态上传包固定为：`~/Downloads/mengkaile-dist-latest.zip`
- 一次性运行 `npm run setup:git-hooks` 后，pre-push hook 会在每次 push 前执行 `npm run package:dist`；构建或打包失败会阻止 push。
- `mengkaile.top` 不是 GitHub push 后自动部署。静态站仍需把最新 ZIP 中的 `dist/` 内容上传/替换到云端对应目录；后端代码如有更新也需按服务器现有部署方式更新。

## 2. 长期产品目标与不可破坏规则

- 产品是类似 JLCFA/MayCAD 的三语（中文、英文、日文）3D 铝型材 DIY 设计器，设计结果可编辑、预览、报价、加入购物车，并输出客户/工厂 PDF、生产 JSON 和 Excel。
- 品牌中文名是“萌开了”。IKEA 产品中文名已经从误写的“书法特”统一为“舒法特”；历史订单分类仍兼容旧名称。
- 设计器可使用 SVG/简化 3D 几何；商品页、购物车和客户/工厂 PDF 必须保留原始 JPG 实物图，不能被设计器 SVG 覆盖。
- 7号 L/T 连接板的物理厚度固定为 2mm，1515/2020 共用款及 3030/4040 都遵守。
- 2047 的 B、D 面各有三个攻丝/加工位置；不要退回普通 2040 的处理。
- AI 只负责未来的设计建模建议，最终必须由人预览、编辑和确认后下单。现阶段 MayCAD PDF/AI 推断保持关闭，没有配置 AI API key；只启用确定性 `.scene` 导入。

## 3. 已完成的主要能力

### 3D 设计器

- 中文/英文/日文随时切换，与站内其他页面一致。
- 改进了移动、吸附、边缘净空距离、干涉提示、场景内旋转入口、右键提示、复制和 Shift+平移复制。
- 旋转/移动即使产生干涉也保留操作，相关型材和项目节点高亮异常，不再因为碰撞强制回滚。
- 配件支持锁定位置、自动识别/放置等基础机制；9号三通只允许绑定真正三根互相垂直且端点汇聚的型材节点。
- 场景 JSON、生产 Excel、购物车和 PDF 保留加工、攻丝、配件规格和适配型号。

### MayCAD 导入

- 默认选择并严格检查 `.scene` 文件；非 `.scene` 会显示三语提醒。
- XML 直接确定性解析，不调用 AI；导入后仍可在萌开了设计器编辑。
- 已维护 MayCAD 与萌开了型材的交集映射；无法确认的型号必须让客户逐项复核选择。
- 当前只承诺导入型材和可识别钻孔，UI 明确提示配件导入仍在开发。
- MayCAD 没有攻丝选项，导入后会提示是否一键给所有型材两端攻丝。

### 商城、订单和 PDF

- 客户地址支持安全删除；客户可删除自己的待处理/已取消历史订单。
- 后台只能删除待处理/已取消订单；已付款、已发货、已送达不可删除，删除前均需确认。
- 手机号支持 `11位手机号-4位虚拟号`，四位虚拟号可选。
- 后台可查看、保存订单 JSON，并对完全相同 JSON 的疑似重复订单提示。
- 修复微信内置浏览器下载问题提示、PDF 空白/分页截断、默认到付逻辑、螺丝规格和重复行等问题。
- 本地和云端 API 配置已分离，目标是不修改生产环境文件即可在本地完成全套测试。

### 性能和商品图

- 移除 `picsum.photos` 外网随机图，使用本地正式商品图或本地占位图。
- 首页有轻量三语加载进度；PDF/预览及大型模块按需加载。
- 商品图、彩色截面图片和“截面本色 vs 截面彩色”说明已经接入；铝板/海洋板图片对应关系已纠正。

## 4. 本次最新发布批次

### 舒法特参数化柜体

- 商品页可按层数/列数，或按不超过客户输入长高的最大完整网格生成，并在新窗口打开同一套可编辑 3D 设计器。
- 篓子净规格：300mm 宽、420mm 深、100mm 高；层距 130mm；柜体外深固定 460mm；全部型材为 2020，默认两端攻丝。
- 长度：`列数×300 + (列数+1)×20`；单片海洋板限制最大 2440mm。
- 立柱孔从底端 130、260、390……递增；最高孔到立柱顶端保留 65mm，因此总体高度为 `层数×130 + 65 + 40`。
- 结构包含底框、N 个中间篓子承托层和顶框，共 N+2 个深度层。最底/最顶 420mm 深度梁只做框架，不装层板托；中间每层共享一根深度型材并按左右实际篓子配置嵌槽式层板托。
- 顶部覆盖一整片 12mm 海洋板。

### 衣柜参数化框架

- 客户输入长宽高后生成恰好 12 根型材：8 根横向 2020、4 根竖向 2040。
- 2040 的 20mm 面朝外、40mm 面朝侧面；横梁采用“横压竖”连接。
- 两个方向的 2020 分别压在 2040 端面不同位置并用沉头螺丝连接；相邻两根 2020 之间以通孔扁头 M6×8 连接。
- 所有模板型材默认两端攻丝，所有可配孔默认生成关联螺丝。

### 清单、PDF 和加工合并

- 螺丝、层板托、连接件等配件按完整购买规格合并同类项；场景中的每个实体仍单独可编辑。
- 逐根型材在设计器清单和客户/工厂 PDF 中可按完整制造规格合并，原始场景、JSON、Excel 继续保留逐根数据。
- 螺丝订货规格统一读取配件规则：20 系圆柱头内六角 M6×30、半圆头内六角 M6×20；衣柜指定扁头内六角 M6×8。27/28mm 等几何渲染长度不再冒充订货长度。
- 型材制造等价允许在“整根型材绕自身长度轴旋转后 100% 重合”时合并。当前仅对白名单普通开放方形型材 `1515 / 2020 / 3030 / 4040` 允许 90°旋转比较，因此普通 2020 的 A→C 与 C→A 通孔可视为相同。
- 封边、圆弧、不对称、多槽、2040 等长方形截面、多攻丝端口和斜切型材均保持方向敏感；无法证明等价就不合并。

## 5. 最新改动的重要文件

- `components/FurnitureConfigurator.tsx`：舒法特/衣柜参数输入和新窗口设计器入口。
- `utils/parametricFurniture.ts`：两套参数化场景、孔位、攻丝和配件生成规则。
- `components/DIYDesigner.tsx`：模板接收、项目清单合并、配件/三通/螺丝与设计器交互。
- `utils/profileManufacturingEquivalence.ts`：保守的型材轴向旋转制造等价白名单与规范化键。
- `utils/cartAccessories.ts`：配件、螺丝和型材的统一显示分组。
- `components/FactorySheet.tsx`：PDF/生产单合并清单和螺丝规格。
- `utils/screwCalculator.ts`：渲染长度与订货 SKU 分离。
- `docs/DIY_DESIGNER_PROJECT_KNOWLEDGE.md`：所有长期产品决定与验收规则。
- `.githooks/pre-push`、`scripts/package-dist.mjs`：push 前构建和 Downloads ZIP 更新。

## 7. 新任务建议的开始方式

1. 运行 `git status -sb` 和 `git log -5 --oneline`，确认 `main` 与 `origin/main` 同步且工作区干净。
2. 完整阅读 `docs/DIY_DESIGNER_PROJECT_KNOWLEDGE.md`、`DIY_DESIGNER_IMPLEMENTATION.md`。
3. 如修改 3D/加工/PDF/购物车，先追踪从场景实体 → CartItem → FactorySheet/JSON/XLSX 的完整数据链。
4. 修改后至少运行 `npm run build`，在 3000 端口浏览器复核，并更新产品知识文档。
5. 用户要求 push 时，确保 `~/Downloads/mengkaile-dist-latest.zip` 同步更新并验证压缩包。
