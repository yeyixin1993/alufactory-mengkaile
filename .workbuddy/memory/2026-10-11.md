## 修掉「GitHub 要传几百张重复图片」——验证产物目录

- 症状（业主要账）：GitHub Desktop 里冒出一大批图片待上传，推得极慢；目录名像是 `.verify-fee`。
- 根因两层：
  1. **每个 `npm run test:*` 脚本都是 `vite build --ssr scripts/verify-*.ts --outDir .verify-xxx`**，
     而 Vite **默认会把整个 `public/` 复制进 outDir**（catalog 159M + images 29M + models 26M ≈ 210M），
     所以每次跑回归都在磁盘上多出一份 210M 的图片副本（`--emptyOutDir` 只管自己那一个目录）。
  2. `.gitignore` 只列了几个写死的名字（`.verify-dist` / `.verify-source-dist` /
     `.verify-furniture-cart-dist` / `.verify-*-dist/`），**`.verify-fee` 不在其中** →
     GitHub Desktop 把它的 183 个文件（214M，全是图片副本）当成新文件要提交。
- 修法：
  - `vite.config.ts` 加 `build.copyPublicDir: !isSsrBuild`（`ConfigEnv.isSsrBuild`，Vite 6 支持）：
    **只有 SSR 回归构建**不复制 public；正常 `npm run build`（非 SSR）照旧复制，dist 部署物不变。
    实测：`test:designer-library-images` 的 outDir 从 216M → **28K**；`npm run build` 后 dist 仍有
    84 张 jpg / 222 个 woff2。
  - `.gitignore` 合并成一条 `.verify-*/`（顺手删掉写死的那几行 + `.verify-*-dist/`）。
    `git check-ignore` 确认 `.verify-fee` 及其内部文件全部忽略；`git status` 从 187 项掉回 10 项。
- 清理：删掉 6 个陈旧产物目录（`.verify-fee` + 5 个 `-dist`），共约 **1.08G**。
  安全性已核：全仓只有 `vite.config.ts` 注释和 `scripts/package-official-handoff.ps1`
  （打包时**排除**这些目录）提到过 `.verify-*`，运行时代码/页面从不读它们；
  真正的图在 `public/images/**`（+ 构建产物 `dist/`），删产物不动图。
- 注意：跑全套 `test:stool-all` 后**又会生成** `.verify-*` 目录（现在每个 28K 级别），
  已被 gitignore，不必再管。
- 验证：`test:stool-all` 全过；`npm run build` 过；dist 图片/字体齐全。
- 本次只动了 `.gitignore` + `vite.config.ts`。**同一工作区还有另一个会话在改**
  （ai_quote.py / QuickQuote.tsx / ProfileEditor.tsx / constants.ts / utils/quickQuoteProfile.ts /
  DIYDesigner.tsx / docs + 未跟踪的 `scripts/verify-vip-plus-danger-fee.ts`，疑似 VIP+ 危险品费用），
  那些文件**别碰**。

## 线上「后台勾选启用 AI 存不住」= admin 页在非安全上下文被 crypto.randomUUID 搞死

- 症状（业主截图）：`/admin/ai.html` 顶部 provider 行空白，勾「启用 AI 咨询」→ 保存 → 返回再进，
  勾**自动取消**，像没保存（实际是**根本没保存的入口**）。
- 根因（agent-browser 实测复现）：线上后台只能通过 `http://47.98.229.152/admin/`（**纯 HTTP**）访问——
  nginx 主域 `https://mengkaile.top/admin/` 被前端 SPA 吃掉（返回 index.html），`/api/` 才代理到 Flask。
  纯 HTTP = **非安全上下文 → `crypto.randomUUID` 未定义**；而 `admin/ai.html` 内联脚本第 8 行就是
  `let adjustmentId=crypto.randomUUID();` → 抛 TypeError → **整段脚本中止**：
  `loadSettings()` 没执行（provider 行空）、`el('saveSettings').onclick` **从未绑定**（点保存无任何反应）、
  顶层抛错又不经过 `run()` 的 catch，所以 `#error` 也是空的 → 完全静默。
  实测：`{secure:false, hasRandomUUID:"undefined", providerText:"", saveHasHandler:false, errorText:""}`。
- 受影响：`crypto.randomUUID` 在 `ai.html`(3 处) + `ai-faq.html`(2 处)；其余 admin 页无 crypto 用法。
  即「AI 问答规则库」页同样是死的。
- 线上真实开关状态（顺手查的，免登录接口）：`POST /api/ai/status` →
  `enabled:false, configured:false, local_answers_available:true`，即**总开关关着 + key 没配**，两边都要做。
- 修法（不动构建）：两个页面各加一个 `newId()`——`crypto.randomUUID` 优先，退回 `crypto.getRandomValues`
  （**非安全上下文里可用**）拼 UUIDv4，最后兜底 Math.random；并加 `window.addEventListener('error',…)`
  把顶层异常写进 `#error`/`#notice`，避免再次静默。已无明文 `crypto.randomUUID()` 调用。
- 验证：把 admin 目录起在局域网 IP 的 http（复刻非安全上下文）实测 → `saveHasHandler:true`、
  `newId()` 输出合法 UUIDv4、错误可见；`node vm.Script` 语法检查两页通过。
- **部署**：`admin/*.html` 是 Flask 静态目录（`app/__init__.py`: `static_folder=admin_dir, static_url_path='/admin'`），
  **不参与 Vite 构建**，改完只需把这两个文件同步到服务器，无需 `npm run build` / dist。
- 免部署应急（先让线上跑起来）：`POST /api/auth/login {phone,password}` 拿 `access_token`
  → `POST /api/ai/admin {"enabled":true,"markup_bps":1000}`。
- 遗留安全问题：后台（含明文 JWT）目前只能走 http://IP，建议后续给 nginx 加 `/admin/` 的 HTTPS location。
