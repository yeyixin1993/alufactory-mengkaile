## 关键环境陷阱

- 本工作区 `vite build --outDir` 配合 `--emptyOutDir` 会对已存在的输出目录触发「safe-delete bulk」守卫（阈值 50 个递归目标）。`.catalog-export/images` + `public` 全量图片会被复制进 outDir，重新构建时递归删除文件数 ≈ 150，触发守卫导致构建失败但不是代码错误。
- 解法：构建前 `rm -rf .catalog-export/images .catalog-export/catalog`（或对 dist 做同样清理），让 vite 的 emptyDir 在空/不存在的目录上启动；或直接跳过 prebuild 用 `npx vite build` 重建主 bundle。

## 表格排版修复（第 8 页 + VIP 第 19 页海洋家具表）

- CSS：`.mkl-marine-table` 加 `table-layout: fixed; width: 100%` + `overflow-wrap: anywhere; word-break: break-word` + 各列 `:nth-child(N) { width: X% }` 显式列宽（图 7% / 名称 18% / 规格 14% / 材质 24% / 颜色 13% / 零售价 9% / 备注 8%）。`.mkl-marine-vip-table` 同套，5 列 18%/16%/24%/18%/24%。
- React 翻译系统痛点：`localizeCatalog` 按整字符串查表，一旦把字段拆成多 `<span>` 子节点会导致子串查询失败，整串翻译键失配而残留原文。
- 解决方案：自定义 `<CellText>` 组件，cn 路径拆 `+`/`/`/`，`为软断点插入 `<wbr>`；en/jp 路径直接 `catalogText(value, language)` 整串查表，返回 React text（让外层 localizeCatalog 二度翻译无害）。关键是 `<CatalogPages>` 需主动接收并向下传 `language` prop（之前漏传导致 en/jp 也走 cn 路径）。
- 调用点：第 8 页公开海洋表 + 第 19 页 VIP 海洋会员价表的 name/spec/material/color/note 全部用 `<CellText value={item.X} language={language} />`。

## Dev Server 常驻

- 用户要求把 `npm run dev` 跑在 http://localhost:3000 给他交互验证语言切换、登录、PDF 下载。`package.json` 的 `dev` 跑 `vite`，`vite.config.ts` 已设 `port: 3000, strictPort: true, host: '0.0.0.0'`。
- 启动后用 `curl http://localhost:3000/` 确认 200。HMR 对 PrintableCatalog.tsx 改动会触发全页面 reload（Fast Refresh 报 `printCatalog export is incompatible`，不影响）。
- QA 脚本 `scripts/check-catalog.tsx` 不在 package.json scripts 中，需要时手动 `npx vite build --ssr scripts/check-catalog.tsx --outDir .qa-dist && node .qa-dist/check-catalog.js` 运行（输出目录要随用随清）。
