## 诊断：设计器「123 个零件 ¥479.4」vs「120 个零件 ¥659.7」价格倒挂（只读分析，未改代码）

用户认为零件补得更多、总价反而更便宜。定位结论：**零件数不是计价单位，估价只对部分 kind 计价。**

### 计价公式（`components/DIYDesigner.tsx`，本文件内的局部函数）

- 汇总：`componentTotal = Σ calculatePrice(item, user)`（第 10570 行），
  仅当 `finishedFurnitureQuote.pricingModel === 'display_rack_3_0'` 时才改用套餐价覆盖。
- `calculatePrice`（第 10253 行）分支：
  - `profile`：(长度/1000) × 型材米价 + 孔(通孔 1 / 沉头 1.8) + 攻丝(每端 `getProfileTapPortCount` × 1.5)
    + **短件附加费：20 < 长度 ≤ 100mm 每根 +5**，再乘数量。
    型材米价见 `constants.ts` `PROFILE_VARIANTS`（3030 本色 oxidized 29 / 电泳 35 / 粉末 41）；
    `natural` 颜色走 oxidized，其余走 powder。
  - `plate`/`pegboard`/`marine_board`：`max(0.2 m², 实际面积) × 单价`——**MIN_BOARD_AREA = 0.2**，
    300×300 的板实际 0.09m² 却按 0.2m² 计；海洋板 18mm 本色 200/m²、彩色 +100/m²。
  - `shelf_support` / `caster` / `foot` / `end_cap` 各有独立价。
  - `connector`/`extruded_connector`/`hidden_connector`/`l_connector`/`t_connector`/`tee_connector`
    走 `ACCESSORY_PRICES[kind][series]`（本色/彩色 × 普通/批量）。
  - **其余 kind（`screw`、`imported_component`）落到最后一个 return，
    `getStandardAccessoryUnitPrice` 对它们返回 null → 取 `item.accessoryPrice || 0` → 一律 ¥0。**

- 123 件里 41 件是导入件，但**每个类别只有 1 份唯一几何**，却按件数各存一份：
  - `shaft_support`（SHF12A）8 件 × 85,806 顶点 = 686k 顶点 = **53.6 MB**
  - `stool_accessory:brake_caster_source` 4 件 × 53,242 顶点 = 212k 顶点 = **20.1 MB**
  - 其余（decorative 8 件 / fixed_support 16 件 / handle 1 件 / shaft 4 件）合计 ~3.2 MB
- **唯一几何各留一份的理论下限 = 11.2 MB → 84% 是纯冗余。**

为什么不能简单删：
- 导入件**就是用内嵌几何渲染的**（`utils/stoolDesignerEngine.ts:3467` → `buildImportedSourceMeshObject` 读 positions/normals/uvs/indices/materials/groups）。
- 丢 `normals` 安全（`utils/importedSourceMesh.ts:242` 缺失时自动 `computeVertexNormals()`）；丢 `uvs` 仅对无贴图的件安全（校验器要求「有贴图必须有 UV」，本夹具 8 个材质带贴图且都落在 4 个脚轮上）。
- 但**任何改动都会破坏几何签名**：`utils/stoolAccessoryAssets.ts` 的 `identifyStoolAccessoryMesh` 对 positions/normals/uvs/indices/materials/groups/boundsMm 做 FNV 哈希，与内置配件资产比对。改了 → `resolveStoolAccessoryReference` 返回 undefined → 导入后 `partCatalogRef` 丢失（`normalizeDesignItems` 会覆盖该字段，文件里预设也救不回来）。
  - 价格不受影响（`classifyImportedComponent` 靠 `sourceMesh.source.semanticType`，如 `stool_accessory:brake_caster_source` 仍能识别成 caster → ¥50）。
  - 受影响的是零件清单里的注册名/材质/规格（`utils/materialList.ts:250-278` 走 `partCatalogRef`）。
- 精度实测：坐标留 3 位小数（最大误差 0.0005 mm）→ 68.7→36.0 MB；再丢法线 → 43.9 MB。

瘦身方案实测：原样 68.7 / 丢法线 43.9 / +坐标3位 36.0 / 去重下限 11.2 MB。

## 22. 源模型「固定支座」= 目录 3号角码（身份 + 图案 + 目录价）

### 业主决定（本次确认）
- 「Source fixed support / `fixed_support`，现价 ¥2.00」**就是 3 号配件**（3号角码）。
- 关联方式：**两个都做** —— 既做身份关联（零件清单/报价单/工厂单按「3号角码」出），
  又补 3 号配件自己的图案。
- 单价：**改用 3 号目录价**（1515/2020 ¥3、3030 ¥4.5、4040 ¥6，彩色另计），
  不再按通用支座 ¥2/件 计。凳子落地价因此 ¥880 → **¥920**。

### 关键判断
先把夹具里 16 个 `fixed_support` 实例的源网格投影出来看：单体 **27×30×30 直角角码、两臂各一孔**，
