## 反复出现的 `.git/index.lock`

今天又出现一次（00:04，0 字节）。**排查结论：确实是僵尸锁，可安全删除。**

已验证排除的因素：

- `lsof .git/index.lock` 空、`pgrep -l git` 空 → 无进程持有；
- 无 `maintenance.*` / `gc.*` 后台维护配置（`git config --list` 只有远端/分支/hooksPath/worktreeConfig）；
- **不是 Git LFS**：`.gitattributes` 只有 `* text=auto`，无任何 filter 规则，且本机 `git lfs` 未安装；
- 仓内 `scripts/*.mjs|*.ts` **没有任何脚本调用 git**（所以 `package:dist` / pre-push 不会留锁）。

→ 两次都是 **0 字节、无人持有**，特征符合「git 操作（很可能是 GitHub Desktop 的后台 index 刷新，或被杀掉的进程）起了个头就断了」。
处理：`rm -f .git/index.lock`。读操作（status/log）不受锁影响，只有写操作（add/commit）会被挡。
