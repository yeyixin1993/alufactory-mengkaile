## 僵尸锁的元凶终于抓到了

- `.git/index.lock` 0 字节、mtime **13:01**，到 22:38 一直挡着 commit。
- `pgrep -l git` 这次报了一个 PID，用 **`pgrep -fl git`（`-f` 才有完整命令行）** 查明是：
  `/Applications/GitHub Desktop.app/.../git --no-optional-locks status --untracked-files=all --branch --porcelain=2 -z`
  —— **GitHub Desktop 的 status 进程从 13:01 卡死到 22:38（9.5 小时）**。
- 但 `lsof .git/index.lock` rc=1（无输出）→ 它**并没有持有这个锁**（而且 `--no-optional-locks` 本就不取锁），
  所以锁仍是无人持有的僵尸锁，`rm -f` 即可。
- 结论：GitHub Desktop 的 status 在这台机器上会被**大文件/大目录**卡死（本仓有 55MB 单行 catalog），
  卡死本身会留下锁文件；下次再遇到，**先 `pgrep -fl git` 看是不是它**，
  必要时重启 GitHub Desktop（不要让它在后台一直转圈），再删锁。
- 注意 `ps` 在沙箱里报 `operation not permitted`，只能靠 `pgrep -fl` / `lsof`。

## 新需求：AI 客服知识闭环（讨论，未开工）

- 现状痛点：网店客服在**微信群**里，外包客服答不上来就 @ 用户本人；同样的问题被重复回答占用大量碎片时间。
- 目标：AI 帮外包客服起草回复 + 从群聊持续沉淀知识 + 同一份知识供网站 AI（`AIChatBar`/`ai_chat.py`）调用。
- 已给结论（方案见对话）：三层闭环 = 采集 → 人工确认的知识库 → 双出口（群内草稿 / 网站 RAG），答错/未命中回流。
- 关键取舍：
  - **不让 AI 直接对客户说话**，只出草稿；价格类永远人工。
  - 静态事实进知识库，**动态数据（价格/运费/库存/排期）走工具调用**查现有 `designerLandedEstimate` 等，绝不让模型背。
  - 采集靠"客服遇到不会的就 @AI"这一行为改造，**不必买会话存档**：企微「办公版 400 元/人/年」仅限金融行业，非金融内部存档只能买服务版 **900 元/人/年**（2026-01-22 起涨价），性价比不成立。
  - 企微智能机器人 API 模式只能收「群里 @ 它」的消息，进不了外部微信客户群 —— 若群里有客户须改用「微信客服」（`sync_msg`/`send_msg`，1:1，无需存档）。
  - 知识库不需要向量库：几百条 QA 用 SQLite FTS5 + LLM 重排足够，省钱且可控。
- 待用户确认：①那个群有没有真实客户在里面 ②外包客服是员工还是外部团队 ③要不要买会话存档（建议先不买）。
