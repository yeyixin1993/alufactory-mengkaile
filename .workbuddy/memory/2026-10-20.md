## 僵尸锁的元凶终于抓到了

- `.git/index.lock` 0 字节、mtime **13:01**，到 22:38 一直挡着 commit。
- `pgrep -l git` 这次报了一个 PID，用 **`pgrep -fl git`（`-f` 才有完整命令行）** 查明是：
  `/Applications/GitHub Desktop.app/.../git --no-optional-locks status --untracked-files=all --branch --porcelain=2 -z`
  —— **GitHub Desktop 的 status 进程从 13:01 卡死到 22:38（9.5 小时）**。
- 但 `lsof .git/index.lock` rc=1（无输出）→ 它**并没有持有这个锁**（而且 `--no-optional-locks` 本就不取锁），
  所以锁仍是无人持有的僵尸锁，`rm -f` 即可。
- 结论：GitHub Desktop 的 status 在这台机器上会被**大文件/大目录**卡死（本仓有 55MB 单行 catalog），
  卡死本身会留下锁文件；下次再遇到，**先 `pgrep -fl git` 看是不是它**，
  必要时重启 GitHub Desktop（不要让它在后台一直转圈），再删锁。
- 注意 `ps` 在沙箱里报 `operation not permitted`，只能靠 `pgrep -fl` / `lsof`。
