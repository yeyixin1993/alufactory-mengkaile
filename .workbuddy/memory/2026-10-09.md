## 「游客不能发消息 / 开始咨询按钮灰」——其实是两件事叠在一起

1. **5001 和 3000 都没在跑**（我上一轮收尾按 PID 清过 3000，`dev:deepseek` 是父子一起退的）
   ⇒ `/api/ai/status` refused ⇒ `status=null` ⇒ 按钮灰。重启 `npm run dev:deepseek` 即恢复。
2. 业主提出「干脆游客必须注册」；我先把事实摆出来（**本地 `local_unlimited` 根本不复现那 3 条**，
   本地游客是不限额度的，页面写着「本地测试 · 不限额度」），业主改口：**保留游客 3 条免费，不改规则**。
   结论：不要再提议取消游客试用。
3. **真凶**：`ai_chat.py` 的 `identity()` 里有 `rate_limit(f'guest:{remote_addr}:{UTC day}', 10)` ——
   同一 IP 每天只能新建 10 个游客账号。本机今天已经 **10/10**（我自己的 curl + 新 profile 也占了几次）。
   只要 localStorage 里没有有效 `mengkaile-ai-visitor`（新 profile / 无痕 / 清过 storage），
   每次打开都新建一个游客，10 次就打满、当天再打开就被拒。
4. **前端把原因吞了（已修）**：`AIChatBar` 的 `/status` catch 原先无条件写
   「咨询服务暂时连接不上，请稍后重试，或先使用快速报价。」，于是「游客名额已满」「访客凭据已失效」
   这类**后端明确给了原因**的失败，看起来跟「后端没开」完全一样 —— 这就是业主误判的根源。
   新增 `statusFailure()`：只有 fetch `TypeError` / 5xx 才说连接不上，其余原样透出后端文案；401 静默（客户端已跳登录）。
